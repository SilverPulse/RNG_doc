# План развития модуля RNG

> Ответственный: Шаимов Богдан | Обновлено: 2026-10-25 (по итогам код-ревью)

## 1. Предложения для своего модуля (разработки для независимости и качества модуля)

### FEAT-RNG-001 (FEAT-001) Архитектурный рефакторинг ООП и внедрение контрактов
- **Статус:** планируется к реализации (приоритет T1)
- **Проблема сейчас:** Ветка `RNG_brench` содержит случайные изменения чужих файлов. Смежные модули жестко импортируют конкретный класс `RandomGenerator`. Выбор алгоритмов (`MRG32k3a`, `Philox`) реализован через антипаттерн условных ветвлений `if-elif-else`. Файловый режим `DataStream` концептуально смешан с математическим генератором ПСЧ.
- **Цель:** Изолировать модуль RNG. Ввести абстрактный контракт (`typing.Protocol`), применить паттерн «Стратегия» для математических движков и полностью отделить чтение статических датасетов от генерации случайных чисел.
- **Предлагаемое изменение:**
  - Откатить изменения во всех чужих модулях (`git revert`).
  - Создать интерфейс `IRandomSource`.
  - Заменить ветвления в `_get_stream` на реестр стратегий.
- **Входит / не входит:**
  - *Входит:* Очистка PR, создание контракта, архитектурный рефакторинг фасада `RandomGenerator` и `DataStream`.
  - *Не входит:* Перевод чужих моделей на новую архитектуру DI (выполняется владельцами моделей после стабилизации RNG).
- **Входы и выходы:** Единый независимый пакет `RNG`, готовый к интеграции через Dependency Injection.
- **Зависимости:** Нет (полностью внутри зоны ответственности `RNG`).
- **Шаги:**
  1. Выполнить `git checkout dev -- <file>` для сторонних файлов.
  2. Написать `Protocol` и внедрить паттерн "Стратегия".
  3. Изолировать `DataStream`.
- **Проверка готовности:** PR содержит только файлы модуля RNG, устранены архитектурные замечания (P0).
- **Ссылки:** `docs/spec_FEAT-RNG-001.md`, `docs/diagrams.md`.

### FEAT-RNG-002 (FEAT-002) Устранение математических дефектов и универсальные тесты
- **Статус:** реализуется (задача текущей недели, приоритет T2)
- **Проблема сейчас:** В ходе код-ревью выявлены баги ядра P1 (возврат `1.0` в `Philox`, некорректное усечение через `int()` в `get_integer`, зависание при отрицательном `bound`, отсутствие валидации `stream_idx`). В существующих тестах много дублирующегося кода.
- **Цель:** Исправить математические дефекты и перевести проверки на паттерны Data-Driven Testing (`pytest`).
- **Предлагаемое изменение:**
  - Внедрить `math.floor()`, битовый сдвиг для нормализации и Guard Clauses.
  - Написать параметризованные тесты и фикстуры для проверки всех генераторов единым кодом.
- **Входит / не входит:**
  - *Входит:* Багфиксы P1-P2, рефакторинг `tests/rng_tests/`.
  - *Не входит:* Тесты других подсистем симулятора.
- **Зависимости:** Нет.
- **Шаги:**
  1. Исправить баги по карточкам `BUG-RNG-001..006`.
  2. Написать `conftest.py` с фикстурой `rng_engine`.
  3. Прогнать тесты на границы и негативные сценарии (ожидание `ValueError`).
- **Проверка готовности:** Все тесты зелёные, дублирование кода устранено, статусы дефектов переведены в "закрыто".
- **Ссылки:** `docs/audit.md`.

### FEAT-RNG-003 (FEAT-003) Поддержка многоколоночных CSV и именованных ключей JSON в `DataStream`
- **Статус:** идея (отложено)
- **Проблема сейчас:** `DataStream` складывает все числа из файла в одну общую очередь `deque`. 
- **Цель:** Позволить изолированному провайдеру `DataStream` при необходимости считывать конкретную колонку `.csv` или конкретный ключ `.json` для разных подпотоков.
- **Предлагаемое изменение:** Добавить опциональный параметр выбора колонки/ключа.
- **Входит / не входит:** Только доработка `DataStream._load_from_csv` и `_load_from_json`.
- **Зависимости:** Уточнение форматов датасетов у команды моделей.
