## 2. Карточки наблюдений

### BUG-RNG-001 (AUD-001) Округление через `int()` в `get_integer` при отрицательном `min_val`
- **Объект:** `RNG.py::RandomGenerator.get_integer`
- **Категория:** подозрение на баг
- **Наблюдение:** В строке `return int(min_val + v * (max_val - min_val + 1))` используется стандартное приведение `int()`, которое в Python отбрасывает дробную часть в сторону нуля, а не округляет вниз (`math.floor()`).
- **Доказательство:** Строка `RNG.py:304`. На неотрицательных диапазонах (`min_val >= 0`) `int()` и `math.floor()` дают одинаковый результат, но на отрицательных значениях `min_val` это пока не проверялось тестами.
- **Влияние:** Если вызвать `get_integer(min_val, max_val)` с отрицательной нижней границей (например, `get_integer(-2, 2)`), значения из интервала `(-1.0, 1.0)` при отбрасывании дробной части могут переходить в `0`, нарушая равномерность распределения.
- **Как проверить:** Написать тест для `get_integer(-2, 2)` на большой выборке и проверить частоты выпадения чисел; при подтверждении заменить `int(...)` на `math.floor(...)`.
- **Статус:** гипотеза
- **Связь:** пока нет

### BUG-RNG-002 (AUD-002) Отсутствие проверки на отрицательный параметр `bound` в `normal` и `exponential`
- **Объект:** `RNG.py::RandomGenerator.normal`, `RNG.py::RandomGenerator.exponential`
- **Категория:** подозрение на баг
- **Наблюдение:** В методе `normal()` условие выхода из цикла `while True` проверяет `abs(x1 - mean) <= bound`, а в `exponential()` — `bound == 0 or r <= bound`. Если в метод ошибочно передать отрицательный `bound < 0`, условие выхода не выполнится.
- **Доказательство:** Строки `RNG.py:259-277` и `RNG.py:285-292`.
- **Влияние:** При штатных вызовах (`bound > 0` или значение по умолчанию) методы работают корректно, но при передаче отрицательного `bound` возможен бесконечный цикл.
- **Как проверить:** Вызвать `normal(0, 1, bound=-1.0)` в unit-тесте и при необходимости добавить проверку `if bound < 0: raise ValueError(...)`.
- **Статус:** гипотеза
- **Связь:** пока нет

### DEBT-RNG-001 (AUD-003) Повторное создание `DataStream` для одного файла при разных `stream_offset`
- **Объект:** `RNG.py::RandomGenerator._get_stream`, `RNG.py::DataStream`
- **Категория:** вопрос / технический долг
- **Наблюдение:** При `self.engine == 'File'` метод `_get_stream(stream_offset)` для каждого нового `stream_offset` создаёт новый экземпляр `DataStream(filepath=self.filepath)`, заново считывающий тот же файл с начала.
- **Доказательство:** Строки `RNG.py:227-230`.
- **Влияние:** Когда каждому модулю (`MOBILITY_MODEL`, `CHANNEL_MODEL`, `TRAFFIC_MODEL`) создаётся свой экземпляр `RandomGenerator` со своим файлом и используется `stream_offset=0`, всё работает штатно. Вопрос возникнет только в случае, если внутри одного файла потребуется хранить сразу несколько разных потоков данных (несколько столбцов CSV или ключей JSON).
- **Как проверить:** Уточнить у владельцев моделей (`Mobility`, `Channel`, `Traffic`), потребуется ли в будущем хранить данные для разных подпотоков в одном общем файле.
- **Статус:** гипотеза
- **Связь:** `FEAT-RNG-003`

### OPT-RNG-001 (AUD-004) Предвычисление `math.sqrt(variance)` до цикла в `RandomGenerator.normal`
- **Объект:** `RNG.py::RandomGenerator.normal`
- **Категория:** гипотеза оптимизации
- **Наблюдение:** Вычисление `math.sqrt(variance)` выполняется при проверке кэша (`RNG.py:257`) и ещё дважды на каждой итерации цикла `while True` (`RNG.py:270-271`).
- **Доказательство:** Строки `RNG.py:257`, `RNG.py:270-271`.
- **Влияние:** Вынесение расчёта стандартного отклонения `std = math.sqrt(variance)` в начало метода позволит избежать лишних вызовов `math.sqrt` при интенсивной генерации.
- **Как проверить:** Сравнить время выполнения $10^6$ вызовов `normal()` через `timeit`.
- **Статус:** гипотеза
- **Связь:** пока нет

## 3. Что пока не удалось понять

1. **Интеграция предложенной схемы `rng_instances` в основную ветку `Simulation Manager`** — нужно согласовать с Александром (владельцем `Simulation Manager`), подходит ли разработанный вариант с `set_external_datasets()`, `set_rng_engine()` и прямым чтением датасетов в `run_tti` для слияния в `dev`.
2. **Перевод внутренней логики моделей `Mobility`, `Channel`, `Traffic` на `RandomGenerator` в математическом режиме** — нужно уточнить у Андрея и Александра, как именно модели будут забирать свой инстанс из `self.rng_instances` при обычном математическом расчёте (`MRG32k3a` / `Philox`).
