## 1. Цель и назначение

В текущей архитектуре симулятора генерация случайных чисел размазана по модулям и не имеет единого стандарта. Разработанный в ветке `RNG_brench` модуль `RNG.py` (v1.2.0) предоставляет математические алгоритмы `MRG32k3a` и `Philox4x64`, а также механизм чтения статических датасетов `DataStream`.

**Цель этой спецификации** — описать архитектурный рефакторинг модуля `RNG.py` для его корректной интеграции в `PyScheduler v2.0.0`, чтобы:
1. **Исключить жесткую связность кода:** чужие модели не должны напрямую импортировать конкретные классы генераторов, а будут работать через единый абстрактный контракт (`typing.Protocol`).
2. **Чётко разделить ответственность:** математические генераторы ПСЧ (`MRG32k3a`, `Philox`) и потоковое чтение готовых физических выборок (`DataStream`) должны стать независимыми механизмами, а не условными ветвлениями внутри одного класса.
3. **Обеспечить детерминизм:** модуль должен предоставлять чистый механизм изоляции потоков (`stream_offset`), а политика резервирования непересекающихся базовых индексов (`base_stream_idx`) выносится на уровень оркестратора симуляции (`Simulation Manager`).

## 2. Что входит и что не входит в задачу

**Входит (План рефакторинга):**
- **Git-гигиена:** Откат (`git revert`) случайных изменений в чужих файлах (`MOBILITY_MODEL.py`, `CHANNEL_MODEL.py`, `TRAFFIC_MODEL.py`, `UE_MODULE.py`, `TEST_MODULES.py`). В ветке должен остаться только код модуля RNG.
- **Внедрение ООП:** Создание абстрактного контракта источника случайности и применение паттерна «Стратегия» для математических ядер вместо `if-elif-else`.
- **Разделение логики:** Изоляция файлового режима `DataStream` от математического генератора `RandomGenerator`.
- **Устранение дефектов ядра (P0–P1):** Замена `int()` на `math.floor()`, корректная нормализация 64-битных чисел во `float` (для `Philox`), добавление Guard Clauses (`bound >= 0`) и строгая валидация входных параметров.
- **Тестирование:** Покрытие модуля универсальными параметризованными тестами (DDT) и фикстурами.

**Не входит:**
- Внесение изменений внутрь чужих модулей. Владельцы моделей самостоятельно переведут свой код на внедрение зависимостей (Dependency Injection) после поставки абстрактного интерфейса.
- Настройка CLI и механика обработки `DataStream` (Direct Bypass) внутри ядра симулятора — это зона ответственности владельца ядра.

## 3. Архитектура и состав модуля RNG

### 3.1. Из чего состоит `RNG.py`

Модуль будет реорганизован в соответствии с принципом единственной ответственности (SRP). Внутри него будут работать следующие компоненты:

| Класс в `RNG.py` | За что отвечает | Особенность реализации |
|---|---|---|
| `IRandomSource` | **Абстрактный контракт (Protocol)** | Чертеж (интерфейс), описывающий методы `uniform`, `normal`, `exponential`, `get_integer`. Внешние модели зависят только от него. |
| `RngStream` | Стратегия **MRG32k3a** | Алгоритм из NS-3. Использует матричный кэш для мгновенного сдвига состояния генератора по потокам ($2^{127}$ шагов). |
| `PhiloxStream` | Стратегия **Philox4x64** | 64-битный счетчик (10 раундов шифрования). Генерирует 4 числа за проход, нормализуя их к диапазону $[0.0, 1.0)$ по стандарту IEEE-754. |
| `RandomGenerator` | **Математический фасад** | Управляет выбранным математическим движком (через реестр стратегий), кэширует числа для метода Бокса — Мюллера и преобразует базовые числа в требуемые распределения. |
| `DataStream` | Чтение **JSON и CSV** | Изолированный механизм. Выдаёт готовые величины из файлов (используется ядром симулятора в обход математических распределений). |

## 4. Интерфейс модуля (Dependency Injection)

Чужие модули больше не должны импортировать конкретный класс `RandomGenerator` или знать про реализацию алгоритмов. 

### 4.1. Контракт для моделей (Protocol)

На стороне моделей или в общем пакете утилит симулятора описывается интерфейс:

```python
from typing import Protocol

class IRandomSource(Protocol):
    def uniform(self, min_val: float = 0.0, max_val: float = 1.0, stream_offset: int = 0) -> float: ...
    def normal(self, mean: float = 0.0, variance: float = 1.0, bound: float = float('inf'), stream_offset: int = 0) -> float: ...
    def exponential(self, mean: float = 1.0, bound: float = 0.0, stream_offset: int = 0) -> float: ...
    def get_integer(self, min_val: int, max_val: int, stream_offset: int = 0) -> int: ...
```

Внешние модули (например, `MobilityModel`) просто объявляют зависимость в своём конструкторе:
```python
class MobilityModel:
    def __init__(self, rng: IRandomSource):
        self.rng = rng  # Инъекция абстрактного источника
```

### 4.2. Инициализация и владение потоками в ядре симулятора

Только оркестратор (`SimulationManager`) знает о конкретных классах генератора. Он создаёт объекты и раздаёт им уникальные базовые индексы, выполняя роль фабрики:

```python
from RNG import RandomGenerator

# Ядро выступает владельцем политики распределения индексов
math_rng = RandomGenerator(engine='Philox', seed=12345, base_stream_idx=100)

# Ядро внедряет зависимость (DI) в модель
mobility = MobilityModel(rng=math_rng)
```

**Особенности механики потоков:**
- Параметр `stream_offset` (смещение) прибавляется к `base_stream_idx` при каждом вызове. Это позволяет одной модели развести разные параметры по соседним подпотокам внутри своего выделенного диапазона.
- Выбор алгоритма реализуется через **реестр стратегий**. При передаче неизвестного значения `engine` генератор обязан немедленно выбросить `ValueError`.

## 7. Способы проверки и критерии готовности

Работа по рефакторингу считается выполненной, когда:
1. **Валидация интерфейсов:** Модули симулятора взаимодействуют с `RNG` исключительно через `IRandomSource`, без прямого импорта классов модуля.
2. **Изоляция дефектов:** Все баги из таблицы P0–P1 устранены, `Philox` математически гарантирует возврат $[0.0, 1.0)$.
3. **Чистота тестов и Git:** В PR присутствуют только файлы модуля, а тесты используют параметризацию без дублирования кода.
